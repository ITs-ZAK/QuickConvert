# QuickConvert v0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the current branded QuickConvert application as reproducible GitHub Release `v0.2.0` with a correctly named and branded Windows installer.

**Architecture:** Treat the repository version and Inno Setup version as one release contract protected by the existing console test suite. Let the tag-triggered GitHub Actions workflow perform the authoritative build and upload; local verification blocks tag creation, while public GitHub API checks prove that the workflow produced the required assets.

**Tech Stack:** .NET 8, C#, PowerShell, Inno Setup 6, GitHub Actions, Git tags, GitHub REST API.

## Global Constraints

- Product version is exactly `0.2.0`; Git tag is exactly `v0.2.0`.
- GitHub Release name is exactly `QuickConvert v0.2.0`.
- Windows installer name is exactly `QuickConvert-0.2.0-win-x64-setup.exe`.
- `Directory.Build.props` and `installer/QuickConvert.iss` must carry the same version.
- `v0.1.0` and all of its existing assets remain unchanged.
- The release must be built by `.github/workflows/release.yml`, not uploaded manually.
- The release is incomplete unless it contains the Windows installer and `SHA256SUMS.txt`.
- Keep `SetupIconFile`, `WizardSmallImageFile`, and `UninstallDisplayIcon` bound to the QuickConvert branding assets.
- Do not add Authenticode, store publication, or new product branding.

### Task 4: Publish tag-triggered GitHub Release

**Files:**
- External state: `origin/main`
- External state: Git tag `v0.2.0`
- External state: GitHub Actions Release run
- External state: GitHub Release `v0.2.0`

**Interfaces:**
- Consumes the verified commit at local `main` from Task 3.
- Produces `origin/main`, annotated tag `v0.2.0`, and public GitHub Release assets.

- [ ] **Step 1: Synchronize and push main without rewriting history**

```powershell
git fetch origin
if ((git rev-parse origin/main) -ne (git merge-base origin/main main)) {
    throw 'origin/main is not an ancestor of local main'
}
git push origin main
if ((git rev-parse main) -ne (git rev-parse origin/main)) {
    throw 'origin/main does not match local main after push'
}
```

Expected: push is fast-forward and local `main` equals `origin/main`.

- [ ] **Step 2: Create and push the annotated version tag**

Before creation, confirm `git tag --list v0.2.0` prints nothing. Then:

```powershell
git tag -a v0.2.0 -m "QuickConvert v0.2.0"
git push origin v0.2.0
```

Expected: GitHub accepts the new tag and starts `.github/workflows/release.yml`.

- [ ] **Step 3: Poll the public release API until completion**

Poll no faster than once every 15 seconds for up to 20 minutes:

```powershell
$headers = @{ 'User-Agent' = 'QuickConvert-release-verifier' }
$deadline = [DateTimeOffset]::UtcNow.AddMinutes(20)
do {
    try {
        $release = Invoke-RestMethod `
            -Uri 'https://api.github.com/repos/ITs-ZAK/QuickConvert/releases/tags/v0.2.0' `
            -Headers $headers
    } catch {
        $release = $null
    }
    if ($null -eq $release) { Start-Sleep -Seconds 15 }
} while ($null -eq $release -and [DateTimeOffset]::UtcNow -lt $deadline)
if ($null -eq $release) { throw 'v0.2.0 release did not appear within 20 minutes' }
```

- [ ] **Step 4: Validate public release identity and assets**

```powershell
if ($release.name -ne 'QuickConvert v0.2.0') { throw "Unexpected release name: $($release.name)" }
if ($release.tag_name -ne 'v0.2.0') { throw "Unexpected tag: $($release.tag_name)" }
$assetNames = @($release.assets | ForEach-Object name)
if ($assetNames -notcontains 'QuickConvert-0.2.0-win-x64-setup.exe') {
    throw 'Windows installer is absent from v0.2.0'
}
if ($assetNames -notcontains 'SHA256SUMS.txt') {
    throw 'SHA256SUMS.txt is absent from v0.2.0'
}
$release | Select-Object tag_name, name, published_at, html_url
$release.assets | Select-Object name, size, browser_download_url
```

Expected: the public release has the exact tag, title, installer, and checksum asset. Report its `html_url` to the user. Do not modify `v0.1.0`.
